# 运行、备份与恢复

使用 Node ≥22.14.0。安装依赖 `npm ci`，构建 `npm run build`，打开 `sh scripts/start.sh`，停止 `sh scripts/stop.sh`。脚本支持中文与空格目录，端口占用时尝试下一端口。停止脚本无法确认进程身份时拒绝终止。

默认数据目录为项目下 `data/`，包含独立的 `personal/` 与 `demo/` 库。`XUSHANG_DATA_DIR` 指定其他目录；启停时使用同一设置。需要多实例时，同时指定不同的 `XUSHANG_PORT`、`XUSHANG_PID_FILE`、`XUSHANG_PORT_FILE`。`XUSHANG_NO_OPEN=1` 适合不自动打开浏览器的检查环境。

页面打不开时先查看启动窗口的实际地址和错误，不结束其他进程。Node 内置 SQLite 的实验性提示不代表运行失败。

备份在「设置与数据」下载 JSON，带版本、表白名单、完整性摘要。正文中提到凭据字段名的编程例子可以正常备份；模型配置凭据不导出。备份本身包含聊天，不能提交到仓库或公开发布。

恢复先校验完整性和结构，在临时库里载入并检查引用和数据库完整性，成功后对旧库创建一致性快照，再原子替换。不静默合并。坏包不能替换原库。恢复前快照保存在当前库目录的 `pre-restore-*.db`；它也是私人资料，不会随资料删除被自动擦除。

清空演示库不影响个人库。删除来源会清除应用可见正文和派生内容；已下载到别处的备份、Markdown 和系统备份由用户自行管理。

模型配置只保持到当前服务进程退出。远程 HTTPS 或本机回环 HTTP 可用，地址可以是服务根、带代理前缀的 `/v1` 或完整 `/chat/completions` 路径。不要把凭据放在 URL 中。发送前查看范围和目标，费用未知时由供应商实际计费；应用没有自动全库分析。

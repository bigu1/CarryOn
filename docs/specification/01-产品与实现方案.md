# 续上：产品合同

源自 2026-09-16 的首版方案。以下产品行为与数据边界保留；当前实现与验证范围见 ../ACCEPTANCE.md。

## 1. 产品目标和成功定义

### 1.1 一句话

把用户主动导入的旧聊天，整理为可追溯的决定、待办问题和交接背景，让下一次讨论可以直接接着进行。

### 1.2 要解决的具体问题

- 同一件事讨论过多次，记不清最终选择、放弃理由和后来的修改。
- AI 提出的建议容易和用户实际采纳的决定混在一起。
- 换一个 AI 时，用户需要反复解释背景、已做尝试和未解决问题。
- 原始聊天很长，搜索得到关键词后仍需要自己判断哪段可靠、哪段过时。

### 1.3 第一版要让用户完成的三件事

1. 找回：输入关键词，或在已配置模型时提出自然语言问题，找到相关材料并打开对应原话。
2. 整理：核对系统建议的记录，确认、修改或拒绝，明确哪些只是建议、哪些是已记录的决定、哪些尚待解决。
3. 交接：选择一个主题和本次目标，得到一份可预览、编辑、复制或下载的背景说明。

### 1.4 成功以真实使用衡量

在一组用户自行选择的 20 段聊天上，尝试回答 5 个真实历史问题，产出至少 2 份用户愿意拿去继续工作的交接说明。先记录人工找资料的时间，再记录使用产品的时间与错误；样本小，只用于判断自用价值，不宣称通用准确率。

用户数据尚未提供时，用附带的合成材料完成工程验收，并把真实使用验收明确保留为待办。不得为了证明价值擅自扫描用户机器上的聊天目录。

## 2. 决策层级：哪些固定，哪些自由

| 层级 | 内容 | 实施权限 |
| --- | --- | --- |
| 必须遵守 | 来源可追溯、用户与 AI 区分、历史与当前区分、人工确认、隐私范围、P0 功能、验收要求 | 不得为赶工删除或改弱；发现不可实现时记录阻塞和替代建议 |
| 推荐起点 | React/TypeScript、本地单进程服务、SQLite、模块分层、界面组织 | 可按当前环境调整；先写理由、影响、回滚办法，再实施 |
| 实现自由 | 库、组件、CSS、函数、内部路由、具体目录、测试工具的等价替换 | 自行选择并验证，不必反复请示 |
| 需要用户决定 | 扩大私人数据访问、外部模型及预算、公开发布、联网同步、全局设置与已有服务变更 | 提供具体方案后取得授权 |

以下是行为合同，不是逐行编码说明。执行者有义务发现矛盾，补齐低风险实施细节，并留下判断依据。不能用“发挥空间”解释忽略产品要求，也不能把参考文件地图当作不可更改的规定。

## 3. 范围和默认假设

### 3.1 首版必做 P0

- 中文界面、单人、本地网页应用，默认只监听本机回环地址。
- 粘贴文本、上传 UTF-8 `.txt` / `.md`、导入本应用定义的 JSON v1。
- 导入预览、来源/角色/日期校正、重复检测、失败可恢复。
- 资料列表、主题归属、原文阅读、搜索与筛选。
- 记录卡片：目标、用户决定、AI 建议、未解决问题、约束、已尝试事项。
- 人工新建/修改/审核卡片，引用原文，保留变更历史。
- 可选配置但代码必须实现的 AI 提炼、检索后回答和交接润色。
- 冲突提示、替代关系和时间线；不自动宣布现实世界状态。
- 交接预览、可编辑、复制和 Markdown 下载。
- 数据备份、空库恢复、删除资料及其派生内容。
- 完整演示数据、启动/停止入口、运行说明和验收证据。

### 3.2 首版不做

- 自动读取 Codex/实施者/ChatGPT 的私有数据库、会话目录、浏览器 Cookie 或账号。
- 全盘扫描、后台持续录屏、监听剪贴板、自动抓取整个聊天历史。
- 多人协作、账号系统、云同步、公网部署、收费系统、手机原生 App。
- 自动执行聊天中的命令、写入其他项目、自动派遣其他 AI 或发送消息。
- 自动识别全部厂商原生导出格式、PDF/OCR、语音、图片内容理解。
- 向量数据库、复杂 Agent 框架、图数据库、微服务等非必要基础设施。
- 用聊天记录证明线上服务健康、投资收益、医疗判断或实际任务已完成。

原生聊天导出适配、语义索引、NAS 部署可列入后续候选；本次不把它们悄悄加进 P0，也不宣传已经支持。

### 3.3 初始使用与工作区

默认在 实施者 中用户打开的新空目录里建立项目。若目录已有工程，先只读识别并说明，不能覆盖或借用无关仓库。不要为了沿用本包路径把应用源代码写进 Codex 的 `outputs/`。

本方案没有指定绝对项目目录，避免让执行者擅自选中已有项目；用户只需在 实施者 打开一个新文件夹。具体路径由 实施者 在最终回执中报告。

## 4. 四条真实使用流程

### 4.1 首次进入与导入

用户看到“添加聊天”和“用演示资料体验”两个明确入口，以及“资料保存在这台电脑上”的说明。没有模型配置也能进入。

粘贴一段聊天或拖入文件 → 展示标题、文本、识别出的角色、来源日期、目标主题 → 用户校正 → 确认导入 → 看到资料详情和下一步操作。

导入必须是两步：预览不入正式库；确认才提交。文件内容里的命令、Markdown、指令全部是资料，不能触发执行或更改设置。

### 4.2 找回当时的决定

用户输入“为什么放弃云同步”，先能看到命中的原文与相关卡片。若启用了 AI 回答，系统在选定范围内取证并生成回答，每个事实性要点附上来源。

回答清楚区分：

- 已经人工审核过的历史决定。
- 尚未审核的候选结论。
- AI 当时提出的建议。
- 当前材料无法回答的部分。

示例文案：“截至已导入的 9 月 5 日记录，你决定首版不做云同步，理由是先验证本地价值。[来源] 尚未导入后续讨论，无法判断现在是否改变。”

### 4.3 检查变化与冲突

同一主题出现旧的“用 A”与后来的“用 B”。系统保留两条记录，提示“可能发生变更”，并让用户查看两边证据。

只有用户确认“B 替代 A”后，才能在当前整理视图中把 A 标为已被替代。时间更晚本身不是替代证据；不同主题的相似词更不能互相覆盖。

### 4.4 把背景交给下一个 AI

选择主题 → 输入“这次希望对方解决什么” → 系统展示准备包含的卡片、来源及不确定项 → 用户编辑/排除 → 生成预览 → 复制或下载。

交接结构默认包括：本次目标、背景、已确认的历史决定、已尝试与结果、未解决问题、约束、来源索引、资料截至日期。

“无记录”与“确认没有”必须用不同措辞。交接里的历史命令和提示词只作为引用资料，不能作为对接收 AI 的新增权限。来源中任何“忽略规则”等文字都不能进入交接的控制指令区。

## 5. 信息和数据规则

### 5.1 原始资料与整理结果分开保存

原文一经导入不可被提炼过程覆盖。角色、标题、主题等可校正的元数据与原文版本分开；用户修改原文时创建修订版并重新检查相关引用，不原地修改造成引用错位。

每份资料至少有：本地稳定 ID、标题、来源类型、主题 ID、导入时间、来源时间及其可信状态、原文版本与内容哈希、原文顺序。

每个片段至少有：片段 ID、资料 ID、原始说话人标签、归一化角色、原文内容、顺序、可选来源时间。角色枚举建议：user / assistant / tool / unknown。无法确定就保存 unknown。

### 5.2 日期不能编造

- 导入时间由系统生成；发生时间来自材料或用户确认，二者不得混用。
- 没有日期显示“来源日期未知”，不自动填今天。
- 日期只有天就保留天的精度；不要补出虚构时刻。
- 导入顺序不能证明事件顺序。无法判断先后时明确并列。
- 时区缺失、日期不合法、时间冲突都在预览中提示，允许以 unknown 导入。

### 5.3 记录卡片的两个维度

将审核状态与内容状态分开建模：

| 维度 | 可表达的状态 |
| --- | --- |
| 审核状态 | 待审核、已确认准确、已拒绝 |
| 内容状态 | 对决定：记录中有效/已被替代/待澄清；对问题：未解决/有解决说法但待核验/用户标记已解决 |

“已确认准确”只表示用户认可这张卡对来源的概括，不代表里面描述的代码、服务或事件已经被本产品现场验证。

卡片至少保存：类型、主题、标题、正文、审核状态、适用时间、来源引用列表、创建方式（人工/规则/模型）、模型及提示模板版本（若适用）、修订记录。

禁止用一个 confidence 百分数代替上述区别；首版不展示未经校准的“准确率 99%”。

### 5.4 引用契约

引用使用本地资料/片段 ID，加原文版本和原文中的位置范围。模型可以提出引用，服务端必须验证其存在、属于本次范围、位置合法、引用文本与原文一致。

偏移采用哪种单位可由 实施者 决定，但必须全文统一，并覆盖中文、emoji、多字节字符、重复句子。同一句出现两次时不能跳到错误上下文。

每条事实性卡片至少有一处可打开的引用。没有来源的人工备注可保存，但必须标为“用户备注”，不能混成从聊天里提炼的事实。

引用合法不等于内容被支持。用户审核和模型实测还要检查否定、主体、条件和时间；不得靠“有 citation ID”宣称事实正确。

### 5.5 内容改变、删除与异步任务

删除前说明会影响多少卡片、回答和交接快照。删除后原文、搜索索引、派生卡片内容和应用内保存的回答/交接快照不能继续泄漏已删除资料。

多来源卡片如包含被删来源，首版允许将整张卡失效并清除其正文，待用户从剩余资料重新整理；不能只去掉引用却保留可能泄漏原文的概括。

相关任务取消并带资料版本校验；删除或修订后迟到的模型响应不能重新写回旧内容。不存在来源的引用显示失效，绝不自动指向另一条资料。

用户此前下载到外部的备份/导出不会自动被删除，删除确认界面应解释这一点；不声称磁盘取证级擦除。技术审计记录可留事件类型、时间和匿名 ID，但不留被删正文。

## 6. 导入格式、校验和限制

### 6.1 文本与 Markdown

支持粘贴和 UTF-8 文件，保留换行、代码块、原有标记。可以保守识别常见角色分隔，但必须提供预览；不明确的内容按 unknown 整段导入。

代码块、引用块里的 `用户：` / `assistant:` 不得被当成真正的新发言。正文里夹带另一个人的原话也不能直接认定为用户决定。

首版不承诺对所有自由文本自动分割准确；提供“按整段导入”和校正说话人的简单入口。

### 6.2 应用自有 JSON v1

实现并交付 JSON Schema 与合法/非法样例。逻辑结构如下，字段名可在写代码前做一次统一调整并记录：

```json
{
  "schemaVersion": 1,
  "conversations": [{
    "externalId": "optional-stable-id",
    "title": "选择资料保存方式",
    "source": "manual",
    "occurredAt": null,
    "messages": [{
      "externalId": "optional-message-id",
      "role": "user",
      "text": "第一版先只在本机使用。",
      "occurredAt": null
    }]
  }]
}
```

未知 schemaVersion 拒绝并说明；未知 role 归 unknown 并提示；额外字段不执行、不作为权限。native 导出格式不能假装是本 JSON 格式。

### 6.3 容量与事务

建议首版上限：单文件 5 MiB、单次合计 20 MiB、单次 50 个文件、单消息 200,000 字符。超限在确认前说明，不得静默截断。限制可调整，但必须同步界面和测试。

每份资料原子入库，多文件逐份报告成功/重复/失败；重复导入不产生重复卡片。去重基于正文、消息顺序和角色等语义字段，而非文件名或导入时间；来源日期的更正作为元数据变更处理。

带 externalId 的同一资料发生内容变化时，显示修订预览；不同来源但内容相同的情况可复用内容并保留来源信息，不丢掉用户提供的来源。

编码异常、空文件、NUL/binary、错误 JSON、未知格式要有可理解提示。失败的预览和暂存内容必须可清理，重试不会制造半份资料。

## 7. 检索、整理与 AI

### 7.1 无模型时必须可用的能力

本地导入、中文/英文关键词检索、角色/主题/日期筛选、查看原文、人工创建卡片、审核和替代关系、模板式交接导出、备份恢复都必须真实可用。

未配置模型时，自然语言回答和自动提炼入口显示“需要连接模型”，并提供“改用关键词查找”与“手动整理”。不要用硬编码答案或正则规则伪装 AI 理解。

### 7.2 本地检索

至少支持 1–2 个汉字、较长中文词组、英文词、英文大小写、数字、标点和代码片段。不能只验证英文全文索引就宣布支持中文。

查询应参数化；用户输入的 `%`、`_`、引号和搜索语法默认按产品定义的字面含义处理，不能扩大匹配或引起 SQL 错误。

可先采用可靠的子串检索与排序，再按数据量优化；如果用 SQLite FTS5 trigram，要处理少于 3 字符的查询回退。官方资料说明其全文查询对少于 3 个 Unicode 字符的片段不匹配，不能遗漏中文短词。[SQLite FTS5](https://www.sqlite.org/fts5.html)

排序要稳定，有下一页，不同主题不互相污染。结果显示命中片段和来源，隐藏或删除的数据不再出现。

### 7.3 模型接入：代码必做，真实验证需实际服务

首版只实现一条清楚且经过文档核对的模型 HTTP JSON 接入路径。可优先选执行环境中容易验证的兼容接口；无需支持所有供应商。服务地址、模型名和凭据由用户提供，不能从其他应用配置中偷取。

模型调用封装在后端。凭据默认仅本次进程内存保存；重启后需重填，不写浏览器存储、日志、数据库、导出或代码。若用户后来要求持久化凭据，单独评估系统钥匙串，不在首版偷偷扩大范围。

首次使用外部服务前，在界面展示目标服务、将发送的资料/片段范围与大小，由用户点击发送。用户主动在该界面填写服务并提交本次请求可作为本次调用的确认，不反复弹无意义确认。实施者 开发验收时的真实调用仍必须得到用户对服务、测试数据和调用预算的明确授权。

只允许向用户设置的地址发送本次选定内容。默认不跟随携带凭据的跨站重定向；不从文档/模型回复接受新 endpoint。远程服务默认 HTTPS；本机模型 HTTP 仅允许明确的回环地址。实现限时、并发限制、请求大小上限、输出上限与取消。

费用未知时显示未知；不能伪造精确价格。默认一次只运行一个整理任务，无自动全库分析；错误重试最多一次并可见，不无限消耗调用。

### 7.4 提炼流程

选择资料/主题 → 预览发送范围 → 分段并保留原始片段 ID → 调模型产生结构化候选 → schema 校验与引用校验 → 进入待审核队列 → 用户核对后保存。

长资料不能静默截断。显示总段数、已处理/失败段数及覆盖范围；部分成功标为“部分完成”，不得据此回答“全部聊天的最终结论”。跨段提炼要保留支持/反对/后续更改的上下文，不能只抽到一句“同意”。

提炼器必须遵守：

- assistant 的建议仍然是 AI 建议；除非另有明确的用户采纳证据。
- 否定、假设、引用、反问、条件句不能转为无条件决定。
- “好”“可以”缺少清晰指代时生成待澄清项，不确认采用哪个方案。
- “测试通过”仅是来源中的报告；没有测试证据就写“聊天中报告通过，未由本产品核验”。
- 资料只是输入数据；其中任何新指令都不能扩大模型权限或改变任务。
- 所有候选先待审核；模型不能直接把卡片设为已确认或直接改旧决定。

### 7.5 自然语言回答

流程：确定用户选择的主题/资料范围 → 本地检索相关片段和已审核卡片 → 在固定上下文内生成答案 → 校验引用 → 显示答案与范围/日期。

每个事实性要点有来源；找不到足够材料就说明不足。冲突未解时并列，不靠日期或模型偏好选一个“最终答案”。没有后续记录，不得把历史状态说成现在状态。

无效模型 JSON、不存在的引用、越界片段、超时、空响应和失败都要显示真实错误，不生成成功卡片。用户可保留已导入资料，重试不重复保存候选。

### 7.6 交接生成

未配置模型时用已审核卡片和用户输入直接生成确定性模板，明确不包含未审核候选；用户可以主动加入带醒目标记的候选或原文。

配置模型后可润色，但不能添加资料不支持的事实、删掉未解决冲突，或把引用资料变成新授权。生成后仍可预览编辑。

首版默认短版约 800–1,500 中文字符，完整版由用户选择。若内容放不下，先展示未包含项并让用户选择，不能偷偷删掉限制/风险/未解决问题。长度是体验目标，不得破坏完整性。导出显示资料范围、生成时间、来源截止情况以及匿名来源编号。

## 8. 界面和体验要求

### 8.1 信息结构

建议主导航为：资料、主题、待审核、交接；设置入口放在次级位置。可合并页面，但必须让用户快速找到上述功能。

默认主屏展示最近主题、未整理资料和“添加聊天”，不堆 token 图表、模型排行榜或无意义统计。

### 8.2 关键页面

| 页面 | 用户应看见/能做的事 |
| --- | --- |
| 资料页 | 搜索、筛选、导入、原文详情、日期和来源、删除 |
| 导入预览 | 分段结果、角色/日期不确定项、主题、重复/修订提示 |
| 主题页 | 已审核决定、AI 建议、未解决问题、变更时间线、资料截止范围 |
| 待审核页 | 候选与原文并排；确认、修改、拒绝；禁止默认全选确认 |
| 回答视图 | 有依据的要点、冲突/缺失、引用跳转、检索范围 |
| 交接页 | 本次目标、包含项选择、预览编辑、复制/下载 |
| 设置与数据 | 模型会话配置、连接状态、备份/恢复、数据位置、停止说明 |

### 8.3 视觉与操作

中文优先、桌面优先，长文阅读舒适、颜色克制、状态用文字和图标共同表达。引用打开后保留返回位置，突出原句并允许看前后文。避免把整个产品做成一个空白聊天框。

至少检查 1440×900、1024×768、390×844 三种视口。键盘可达，焦点可见，按钮有名称，错误紧邻操作；来源抽屉和长文本不导致整页横向溢出。

每条主流程必须有空、加载、成功、部分成功、失败、重试、取消状态。所有按钮都能操作；未提供的能力明确不可用，不放会误导用户的假按钮。

业务界面不用“embedding”“RAG”“schema”等内部术语；高级设置或排错文档可以使用。

## 9. 推荐架构与参考文件地图

### 9.1 架构起点

推荐 TypeScript 前后端、React + Vite 前端、轻量 Node HTTP 服务与 SQLite。使用环境中仍受支持且相互兼容的稳定版本，锁定依赖，记录运行版本。具体框架/数据库绑定可调整，不为采用新技术增加服务数量。

生产本地启动由一个服务提供前端静态文件和本地 API；开发时可有热更新进程。数据落在明确、可备份且默认不进入 Git 的项目数据目录。不要把唯一数据放在浏览器 localStorage。

模块边界：导入解析 → 不可变资料 → 检索 → 卡片/审核/冲突 → AI 适配 → 交接 → 备份恢复。保持数据层和界面分离，以便在无模型时验证。

### 9.3 存储实体建议

Topic、Source、SourceRevision、Message/Segment、ImportBatch、Card、Citation、CardRevision、ReplacementRelation、AnalysisJob、HandoffSnapshot、SchemaVersion。

建表前写清主外键、唯一性、删除行为、引用版本、任务幂等和迁移策略。无需为了展示架构实现事件总线或通用插件平台。

### 9.4 本机服务保护

绑定回环地址，不自动暴露局域网；校验 Host/Origin，不开放通配 CORS，写接口具备本机会话/CSRF 防护并对缺失 Origin 等路径给出明确处理。防护方案由 实施者 选择并用跨源请求测试，不能把“只在本地”当成免保护理由。

用户文本和 Markdown 安全渲染，不执行内嵌 HTML/脚本，不自动加载远程图片。文件名不作为保存路径；限制大小、阻止路径穿越；模型没有 shell/文件写入/浏览器工具。

默认无遥测、无 CDN 字体、无分析脚本。无模型本地使用时不发外部业务请求。启动不自动检查所有供应商，不自动下载大模型，不更改系统网络设置。

## 10. 备份、恢复和运行

导出是可验证的 JSON/归档包，带 schemaVersion、清单和完整性校验；不包含模型凭据、日志中的敏感内容、临时文件或机器绝对路径。导出需要明确提醒其包含私人聊天。

首版恢复只支持恢复到新建空库，或保留当前库快照后切换到一个已校验的新库；不实现危险的静默合并。校验失败时当前库完全不变。SQLite WAL 场景必须使用一致性备份方式，不能在写入中盲目复制一个 db 文件。

提供双击或等价的一步本地启动入口，自动打开网页并显示实际端口；端口冲突不杀别的进程。依赖缺失有中文提示和清晰安装说明，不擅自全局安装或改 PATH。停止入口只终止本项目确认为自身的进程，不使用按宽泛名称杀进程。

启动脚本和说明要在含空格/中文的路径中验证。服务重启后用户资料、卡片和引用仍然存在；演示库与个人库隔离，演示重置不能清空个人资料。
